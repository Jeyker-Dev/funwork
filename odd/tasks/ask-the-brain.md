# Ask the Brain (FunWork task #14, first version)

Objective: a chat inside each project, like Claude or Gemini, with saved conversations, that answers only from the project's data using the user's own AI provider and API key.
Branch: `feat/ask-the-brain` · Delivery: `ask-on-risk`, one commit per task · Test runner: Pest (`php artisan test --compact`).

## Specs

- **S1 — Bring your own provider.** In Settings → Integrations each user adds one or more AI connections. A connection is a provider picked from a list of presets (OpenAI, Anthropic, Google Gemini, DeepSeek, OpenRouter, OpenCode) or "Custom (OpenAI-compatible)" with its own base URL, plus an API key and a model. Presets fill the base URL. One connection is the user's default. The key uses the `encrypted` cast, is `hidden`, is shown only as `••••` plus its last 4 characters, and is never sent back to the browser, written to logs, or included in exception messages. The section explains that a chat subscription (ChatGPT Plus, Claude Pro) does not include API access, and that questions and project context are sent to the chosen provider. *Assumption: exact privacy wording per provider is checked against each provider's docs before shipping.*
- **S2 — Provider port with two adapters.** An `AiProvider` port takes a list of chat messages (system, user, assistant) and returns the answer text and the model that answered. Adapters, built on the Laravel HTTP client with no new package: `OpenAiCompatibleProvider` (OpenAI, Gemini's OpenAI-compatible endpoint, DeepSeek, OpenRouter, OpenCode, Custom) and `AnthropicProvider` on Anthropic's native Messages API, because Anthropic documents its OpenAI-compatible endpoint as meant for testing and comparison, not production. Base URLs, timeouts and default models live in config. A `FakeAiProvider` implements the port for tests. The port must not assume the answer arrives within the HTTP request, so a future local companion provider (#16) can plug in.
- **S3 — OpenRouter stays free by default.** For OpenRouter connections only, requests send a priority list of `:free` models through OpenRouter's `models` parameter, and OpenRouter falls back between them. A per-connection switch "Allow paid models when free models fail", off by default, appends configured paid models. Per OpenRouter's docs, listing only `:free` models keeps a request free, so the balance never goes negative and free access is never cut off. FunWork does no fallback across providers.
- **S4 — Clear errors.** Named exceptions and user-facing messages: invalid or revoked key (401) → "Your <provider> key was rejected. Update it in Settings → Integrations."; out of credit (402, or the provider's billing error) → "Your <provider> account has no credit left."; rate or daily limit (429) → "You reached <provider>'s usage limit. Try again later." (for OpenRouter free models: "It resets at midnight UTC."); timeout or 5xx → "<provider> is not responding. Try again in a moment." A failed reply is saved as a failed message with a Retry action. With no connection, the chat shows a link to Settings → Integrations instead of the composer.
- **S5 — Saved conversations.** Conversations belong to a user and a project, with a title (generated from the first question, editable), the connection used, and timestamps. Messages store role, content, the model that answered, status (pending, completed, failed) and a safe error. Users see and manage only their own conversations, in projects they can view. Rename and delete are supported. Deleting a project deletes its conversations.
- **S6 — Answers grounded in the project.** Each reply sends: instructions, the project context from `BuildProjectContextAction`, and the conversation's previous messages. Instructions: answer only from the project context; cite sources inline by ADR code, task ID or notebook page title; say so when the answer is not in the context; refuse questions unrelated to the project. The context is rebuilt on every reply so answers use current data. Context and history are capped at named maximum lengths, oldest messages dropped first; when the context is truncated, the instructions say it is partial.
- **S7 — Replies run in the background.** Sending a message saves it, creates a pending assistant message and queues a job that calls the provider. The chat shows a typing indicator and refreshes with `wire:poll` only while a reply is pending, like the repository sync card. AI calls never block a web request or an Octane worker.
- **S8 — Chat UI.** A project page "Ask" reachable from the project navigation, laid out like Claude or Gemini in FunWork's style: conversation history in a side column (new chat, rename, delete, most recent first), the message thread with rendered Markdown, source references styled as chips, the model name on each reply, copy and retry actions, a composer that sends with Enter and adds a new line with Shift+Enter, and example questions in an empty conversation. Works at phone width with the history in a drawer. UI is prototyped in Stitch before code.
- **S9 — Limits.** A per-user rate limit on sent messages (named constant, for example 30 per hour) with its own message, enforced at the boundary.

### Out of scope (later)
- Proposed tasks from answers (structured output with confirmation).
- Kickoff mode that turns a conversation into a project (already possible today through MCP and an external agent, task #63).
- Local companion provider that uses the user's own Claude Code, Codex or Gemini CLI subscription (task #16).
- Streaming answers token by token.

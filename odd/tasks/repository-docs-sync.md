# Repository Docs Sync (GitHub webhook + personal token)

Objective: keep project notebooks in sync with each repository's `docs/` folder automatically on every push to the default branch, without GitHub Actions, local scripts or SSH.
Branch: `feat/repository-docs-sync` · Delivery: `ask-on-risk`, one commit per task · Test runner: Pest (`php artisan test --compact`).

## Specs

- **S1 — Sync from files, not from disk.** `SyncDocsNotebookAction` receives the Markdown files as `[source_path => body]` instead of reading a directory. Reading `docs/` from disk moves to the `funwork:sync-docs` command, which keeps its current signature and behavior. Create, update and prune rules stay the same (prune only touches pages with a non-null `source_path`). The whole sync runs in one transaction.
- **S2 — Stable `source_path` keys.** Keys stay `docs/<relative path>` for the default docs path, so projects synced today by script (Ahorra, project 2; LifeForge, project 3) are updated in place, not duplicated, when they switch to a repository connection. Files under `archive/` stay excluded.
- **S3 — Full tree on every sync.** Each sync fetches the complete docs tree of the repository at the pushed commit (GitHub Git Trees API, recursive), never only the changed files, because prune deletes every page missing from the set.
- **S4 — Repository connection per project and area.** A project has zero or more repository connections. Each stores: repository (`owner/name`), branch (default branch by default), docs path (default `docs`), optional area, personal access token, webhook secret, last synced commit SHA, last synced time, status (`active`, `broken`) and last error. One connection per (project, area); at most one without area. Only the project owner can view or manage its connections.
- **S5 — Secrets.** The personal token and the webhook secret use the `encrypted` cast and are `hidden`. The token is never sent back to the browser (shown as `••••` plus its last 4 characters) and never logged. The webhook secret is generated by FunWork, shown so the user can paste it into GitHub, and can be regenerated.
- **S6 — Docs source port.** A `RepositoryDocsSource` port returns the Markdown files of a connection at a commit. The first adapter uses the connection's personal token over the GitHub REST API (Laravel HTTP client, no new package). A future GitHub App adapter implements the same port. Limits as named constants: maximum files and maximum bytes per file; over-limit files are skipped and reported, not truncated.
- **S7 — Webhook endpoint.** A public route per connection receives GitHub `push` events. It verifies `X-Hub-Signature-256` (HMAC SHA-256 with the connection secret, constant-time compare) before anything else and answers 401 on mismatch. It answers 200 to `ping`. It ignores pushes to other branches and pushes that do not touch the docs path. Otherwise it queues the sync job and answers 202. The endpoint is excluded from CSRF and rate limited.
- **S8 — Queued, idempotent sync job.** One job per connection at a time (unique job). It skips when the commit SHA equals the last synced SHA. On success it stores SHA and time and clears the error. A "Sync now" button runs the same job for the current head of the branch.
- **S9 — Broken connections are visible.** When GitHub answers 401, 403 or 404 (expired or revoked token, renamed or removed repository), the connection becomes `broken`, stores the error, stops syncing and the owner gets an in-app notification (database channel, plus web push when subscribed). Updating the token or settings and syncing successfully sets it back to `active`. A failed sync never deletes pages.
- **S10 — Settings UI.** Project settings get a "Repositories" section to add, edit, sync now and remove connections, with copy buttons for the webhook URL and secret, step-by-step instructions to create a fine-grained token (read-only Contents) and the webhook (content type `application/json`, push events only), and each connection's status, last sync and last error. Removing a connection keeps the notebook and its pages. UI is prototyped in Stitch before code.
- **S11 — In-app onboarding.** The notebooks empty state offers "Connect a repository" linking to the Repositories settings, so users discover the docs workflow inside the app instead of in external documentation. UI is prototyped in Stitch before code.

### Out of scope (follow-ups)
- GitHub App adapter for one-click setup (product-wide path).
- MCP `sync_doc_page` upsert by `source_path` (fallback A from the original plan).
- "Docs stale" health rule (belongs to #64).
- Agent kit: copyable `AGENTS.md` block and MCP config.
- GitLab and other hosts. Two-way sync (notebook to repo) is explicitly rejected.
